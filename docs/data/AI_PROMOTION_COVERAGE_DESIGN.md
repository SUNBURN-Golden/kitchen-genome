This is an important correction to a simple “awards never count” reading. ### Code gaps found in this review

1. `promotion._original()` returns `None` for both a contradictory original and a rejection by `lineage._source()` (banned host, search/event tier, disabled source, `manual_only`/`prohibited` policy). Telemetry cannot distinguish `no_original` from `unsafe_source` without a promotion-local source classifier or a reason-returning refactor used by every caller.
2. `_original()` checks only that `entry['quote']` occurs in the sanitized, NFC-normalized text. It does not use `extraction.span_start/span_end`. The spans in the live rows do equal the quote for the samples checked, but the build must map raw-text offsets into the sanitized text (or re-locate the exact occurrence) rather than compare offsets across representations.
3. `_location()` returns a city but a country only from `promotion.COUNTRIES`. `lineage.CITY_COUNTRY` already has `paris → FR`, but promotion does not use it. The wkorea SEOK quote would get `city='파리'` and no country today.
4. `_promote()` handles a duplicate `review_id` by moving the later entry to the first decision without evaluating its own quote or endpoints. The current seed has no duplicate or missing review IDs, but legacy rows and rollback replays need a defined `duplicate_review_id` outcome.
5. `_spellings()` alias expansion helps identity resolution, but it runs after `_parse()`. The new typed-span matcher must pass attested spellings into `_site_matches`, `_branch` and `_chef`; it must not allocate a second identity for `강민구` / `Mingoo Kang` or `SEOK` / `세옥`.
6. `_parse()` and `_korean_relation()` already cover simple venue-first appositions (the three probe rows), some chef-first leadership verbs and bilingual suffixes. They do not cover the parenthetical cell, most subject-elision forms, the short-reference field, or the completed-opening forms in this corpus; the new matcher must preserve the covered apposition while broadening the rest.

### Yield risk

A manual read of the 67 suggests roughly 12 are award/ranking/contest-only, about 10 are institutions, media or corporate/hotel appointments, about 5 have the venue absent, 1–2 are generic or planned/tentative openings (`개업 연기 끝 ... 가오픈`), and several are bare possessives or ambiguous profile-table rows. That leaves roughly 30–42 with an explicit label-compatible predicate, before branch and chef resolution (the categories overlap, so this is an estimate rather than a subtraction). The 40 target is therefore at the edge. The build must establish the exact yield, report any shortfall by reason with representative reviews, and must not loosen a guard to reach 40.

## Record the first failing gate

Implement telemetry against the existing binder first. Have the checks in `_original`, `_parse` and identity resolution return the actual failing gate to `_promote`. Keep `backfill()`'s integer result for callers; add a private reconciliation/histogram helper. Decide each entry once across candidate matches. A later valid occurrence can succeed even if the first literal match fails. Across unsuccessful alternatives prefer a guard that applies to the target, then the furthest gate reached.

| Gate in evaluation order | Reason on failure |
| --- | --- |
| Review and publication eligibility | `tombstoned` for a withdrawn review, logged rollback or known venue tombstone. Check the review-level tombstone before the original lookup; check venue aliases again after spelling resolution. Otherwise use `invalid_annotation` for bad or missing identifiers, badge or provenance (`badge != 'AI 검토'` or `provenance != 'ai_reviewed'`); `duplicate_review_id` when a later entry repeats a review ID already decided and is not an identical move; `unsupported_label`; `unsafe_source` for `site_publish.safe_url()` failure or a `lineage._source()` URL/host/tier/policy rejection; or `unsafe_quote` for an overlong, redacted or injection-flagged quote. |
| Endpoints | `no_chef`, then `no_venue` for missing values. Use `invalid_endpoint` for generic, identical or malformed endpoint names. A well-formed short chef reference (`손 셰프`, `Chef Kang`) goes to subject resolution. |
| Source and target checks | `no_original` for a contradictory review/subject, quote or source, a quote occurrence that cannot be located in the retained text, or missing evidence required by a contextual rule. | Canonical identity | `branch_unresolved` for ambiguous, conflicting or unusable restaurant identity; `chef_unresolved` for an unresolved person. Preserve the per-review savepoint around branch and chef creation. |

### Skip table and histogram

Persist the **current backlog** in a private SQLite table:

```sql
CREATE TABLE ai_promotion_skip (
  unlinked_index INTEGER PRIMARY KEY,   -- zero-based index into the final unlinked array
  review_id TEXT,
  reason TEXT NOT NULL,
  extraction_id TEXT,
  quote_key TEXT
);
```

`unlinked_index` points into the final `ai_reviewed_unlinked` array and disambiguates legacy rows with missing or duplicate IDs. `extraction_id` and `quote_key` let a later pass detect that the array moved; do not trust a position whose fingerprint no longer matches. **Rewrite the table from scratch on every pass** (`DELETE` then `executemany INSERT`) inside the caller's write transaction, after moves, withdrawals and the final venue-only sweep. The backlog is bounded at roughly 225 rows, so a full rewrite is simpler and safer than incremental reconciliation. If the transaction rolls back, the previous table remains consistent with the previous seed; the next pass rewrites it. Store one row per remaining entry, including unsupported labels. A moved entry gets no row. Preserve the existing venue-only reattachment for eligible annotations, but exclude guarded and tombstoned entries from that sweep so they stay unlinked even when a matching holder exists.

Append `promotion_skips=<compact sorted JSON object>` to the existing `AI_REVIEW` line, for example:

```text
AI_REVIEW approved=319 ... promoted=4 unlinked_remaining=225 promotion_skips={"institution":11,"no_chef":61,"no_clause":46,"no_original":9,"no_relation":38,"no_venue":27,"temporary":12,"unsupported_label":21}
```

The counts above are illustrative and sum to 225. The JSON must be compact (no spaces), so the shell's whitespace tokenization and `record_ai_reason()` are unaffected. The histogram counts final rows, sums to `unlinked_remaining` and prints `{}` for an empty backlog. Replace it at each `_finish_delivery` pass while accumulating new-link counts as today; reset `stats['promotion_skips']` at the start of each pass so a no-op second pass cannot print a stale histogram. The shell already forwards the last `^AI_REVIEW` line from each invocation; because the daily pipeline invokes AI review twice (the backlog pass and the post-collection pass), the logged histogram is the final pass's snapshot. SQLite holds the per-review reasons and the log holds only aggregate counts. Keep both out of the seed, projected rows, page builders and feeds.

Handle empty input, empty promotion state and the no-open-reviews delivery path: `review._finish_delivery()` sets `{}` when there is no backlog and still writes/reconciles the table when `promotion.annotations(seed)` or `seed[promotion.KEY]` exists.

## Bind the quote before resolving identities

1. **Locate the evidence.** Carry the matched review subject, fetch/document identity, normalized source text and quote occurrence through `_original` in memory. Use the extractor's raw-text `span_start/end` when it exactly matches the quote, then re-locate that quote in the sanitized/NFC text; do not compare offsets across representations. If offsets are absent or shifted by sanitization, allow a unique exact occurrence. Repeated text with conflicting local subjects, moved spans or a mismatched body cannot establish a contextual binding. Legacy approvals with missing raw data retain the existing literal-quote path and its independence ceiling.
2. **Match typed spans.** Enumerate non-overlapping occurrences of each endpoint and its attested spellings. Handle quotes, full-width parentheses, Latin case and Korean particles while retaining offsets into the original quote. A bilingual gloss such as `세옥(SEOK)` supplies two spellings of one venue. A roster cell such as `도우룸 광화문(이준)` supplies two different endpoints. Do not treat a parenthetical matching the chef as a venue alias, or a parenthetical matching the venue as a chef alias; do not manufacture aliases from arbitrary parentheses, family names, automatic romanization or fuzzy substring matches. In `오스테리아 샘킴(샘킴)`, bind the parenthetical chef occurrence, not the first `샘킴` inside the venue.
3. **Apply exclusions to every new route.** Check the target and its spellings for the existing institution rules, corporate/legal/group and department-store names, research institutes, tableware brands, media productions, TV and YouTube channels. Extend the existing `INSTITUTION`/guard set for at least `백화점`, `연구소`, `연구원`, `재단`, `협회`, `브랜드`, `방송`, `예능`, `TV`, `유튜브`, `채널`; examples to reject include `신세계백화점`, `사찰음식 연구소`, `라 리스트(La Liste)`, `마스터셰프 코리아`, `흑백요리사`, `더본코리아` and `가온소사이어티`. Inspect the enclosing source sentence/list heading for a clipped event roster, guest shift, sponsorship, executive appointment, contestant, judge or appearance; Korean cues include `승진`, `선임`, `임원인사`, `출연`, `수상`, `우승`, `순위`, `프로필`. Enforce the named backfill exclusions `오닐`, `오닐(ONIL)`, `DOORI`, `주052` across their Korean and English spellings, including bare `DOORI(chef)` entries. This must be a private constant/list in promotion, not a public seed tombstone, and it must apply even when the quote says `정식 오픈`/`정식 개점`. Treat it as a backfill exclusion; a later review that establishes a genuinely separate permanent outlet under one of these names needs a human decision, not an automatic override. A named restaurant *inside* a hotel can qualify when the quote makes the restaurant the employer; the hotel/org is not the venue. Preserve the existing narrowly scoped completed-pop-up prefix exception for a separately established permanent outlet. Preserve CONTEST's requirement for an existing outlet match or restaurant wording and all G3 reject cues. A prize or ranking **verb** alone supplies no employment predicate; an explicit `venue의 chef X` apposition is independent evidence and may bind, subject to the contest gate.
